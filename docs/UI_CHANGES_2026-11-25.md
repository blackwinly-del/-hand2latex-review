## 做了什么

### 1. 界面从"上传卡片 + 三栏"改成"左侧任务列表 + 右侧三区工作台"

改动文件：`workbench/static/index.html`

- **左侧常驻任务列表**：以前任务藏在"第一步"卡片的一个下拉框里，要翻页、要点"打开"。
  现在是常驻列表，支持搜索、分页、失败页标记、PDF 标记，点一下直接切换任务。
- **删掉"第一步 / 第二步"步骤编号**：实际使用不是线性走完五步，而是"打开任务、
  来回对照、改代码、看 PDF"。步骤编号反而变成干扰。
- **顶部状态条**：原来 7 个宽块加两个按钮挤成一行。现在压成"图标 + 悬停说明"，
  点右上角 `☰` 才展开完整环境自检表。
- **空状态**：原来下面大半屏是空的。现在有拖拽上传区 + 三步说明。
- **新增拖拽上传**：把图片拖进工作区就开始识别，不用先点选择文件。
- **代码区**：保留行号、报错行红、复核行黄、语法着色。三栏比例调宽代码区
  （`.74fr / 1.52fr / 1fr`，代码栏最小 420px），长行不再被右边界截断。
- **提示方式**：把行内红字错误改成底部浮动提示条，可自动消失，不占据版面。

### 2. 新增桌面窗口外壳

新增文件：`workbench/desktop.py`

启动优先级：

1. **pywebview**（如果装了）——真原生窗口，可设最小尺寸、标题。
2. **系统自带 Edge 的 `--app=URL` 模式**——没有地址栏、标签页、书签栏，
   任务栏独立图标，观感就是桌面应用。零安装、零体积。
3. **默认浏览器**——最后的兜底。

其他行为：

- 端口默认 **8760**，被占用自动往后找 40 个，再不行交给系统分配。
- 窗口用**独立 user-data-dir**（`%LOCALAPPDATA%\Hand2LaTeX\window-profile`），
  不往日常浏览器里塞标签页，也不带平时登录的账号。
- 起服务用 `sys.executable -m uvicorn`，不拼 shell 命令（中文路径/空格路径不会炸）。
- Windows 上加 `CREATE_NO_WINDOW`，不额外弹黑控制台。
- 等 `/api/status` 真的返回 200 才开窗口，避免用户先看到一片白。

命令行：

```powershell
python -m workbench.desktop                        # 开窗口
python -m workbench.desktop --port 8800            # 指定端口
python -m workbench.desktop --headless-seconds 600 # 只起服务不开窗口（自动化验收）
```

### 4. 修掉两个真实用户会撞的 bug

#### bug 1：挂代理的机器上体检误报"Python 运行时不可用"

`Invoke-Captured` 原来用 `Start-Process -RedirectStandardOutput`。这种写法在
**同时存在 `HTTP_PROXY` 和 `http_proxy`** 的机器上会直接抛：

```text
已添加项。字典中的关键字:"HTTPS_PROXY"所添加的关键字:"https_proxy"
```

原因是 .NET 的进程环境变量字典**区分大小写**，而 Windows 环境变量不区分。
挂了代理工具的电脑（Clash、v2ray 等）经常两套大小写都设，于是体检会报
"随包 Python 运行时无法执行"，而实际 `python --version` 完全正常。

改成 `& $exe @args 2>&1 | Out-String` 后不再触碰那个字典。

**实测对比**（两套大小写代理变量都设的情况下）：

| 写法 | 结果 |
| --- | --- |
| 旧 `Start-Process` + Redirect | 抛 `已添加项。字典中的关键字…` |
| 新 `& $exe 2>&1 \| Out-String` | `Python 3.12.10`，exit=0 |

带四个代理变量跑 `launch.ps1 -CheckOnly` 全绿。

#### bug 2：桌面壳自身的健壮性

- 起服务不拼 shell 命令，避免中文/空格路径。
- 窗口起不来时逐级降级（pywebview → Edge → 默认浏览器），不让整个程序挂掉。
- 服务没就绪不开窗口。

## 第二轮界面优化（同日，用户要求「优化界面」后）

上一轮把结构搭好了，这一轮修的是**真实浏览器里测出来的具体问题**，不是凭感觉调样式。

### 5. 上传整体失败时，逐页原因摊在页面上

以前 `upload()` 的 `catch` 只做一件事：`notify(err.message)`。后端 422 会带一段
「每一页都没能识别出来。第 1 页：xxx；第 2 页：yyy」，这段话塞进底部提示条后会被截断，
用户看不到「到底哪页、为什么」，只能反复重传。

现在：`parsePageFailure()` 把长文案拆成逐页条目，`buildUploadFailure()` 兜底
（拆不出页码就整段显示，比如「不是有效图片文件」），渲染成 `.upload-fail` 面板。
面板常驻可关（「知道了」）、下一轮上传会自动清掉。

提示条同时改短：逐页详情在面板里，`notify()` 只留一句「这 2 页都没能识别出来，原因见页面上的说明」。
（第一版没改这句，截图里看到提示条把长文案又原样放了一遍、被省略号截断，属于重复信息。）

### 6. 前端先拦明显不合规的文件，被拒的要说明理由

`onDrop` 以前用 `.filter()` 悄悄丢掉非图片文件——用户拖 3 张、只识别 2 张，不知道为什么。
现在 `precheckFiles()` 逐项检查（扩展名 / 空文件 / 单张 20 MB / 最多 10 页 / 整批 50 MB），
`reportRejected()` 把每个被拒文件名和理由说出来（超过 3 条用「还有 N 个同类问题」收尾）。

### 7. 缩略图按纸面比例留框

`.thumb-img` 原来写死 `height: 178px`。手机拍的整页笔记是 893×1263（比例 0.71）的竖图，
塞进 214×178（比例 1.20）的横框里，`object-fit: contain` 会把图压成中间一条窄条、
两侧大片空白——而这一栏正是用来「对照原图核对」的。改成 `aspect-ratio: 210 / 297` 后，
实测 `fillRatio` 从约 0.35 变成 1.0，手写内容能看清了。

### 8. 窄屏下的三处换行/溢出

用 CDP 在 1440 / 1366 / 1280 / 1180 / 1100 / 1024 六个宽度逐档量出来的：

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| 右栏页签竖排 | 1280px 下「排版 / 问题 / 历史」被压成三个竖着的字柱 | `.seg button` 加 `white-space: nowrap; flex: none`（中文默认可在任意两字间断行） |
| 右栏标题被截 | 标题让位不够，1280px 下截成「预览与检」 | `.pane-title` 加 `nowrap` + `min-width: 0` + `ellipsis`；≤1340px 收紧页签内边距；≤1100px 整块改两行（标题独占一行、页签在下面） |
| 任务项断字 | 1024px 下「1 页失败」从中间断成「1 页失」+「败」 | `.job-meta` 允许 `flex-wrap` 折行，但每个小项 `white-space: nowrap` |
| 横向溢出 52px | 1024px 下整页可横向拖动 | 侧栏 276→220px（≤1100px），三栏最小宽收紧 |

修完复测六个宽度：标题单行且不截断、页签单行、任务项不断字、`scrollWidth - innerWidth = 0`。

## 证据边界（哪些还没证明）

- **无头 Edge 不渲染内嵌 PDF**（没有 PDF 阅读器），所以"右侧预览区是否显示 PDF"
  在无头环境下**无法证明**。已在预览区加"在阅读器中打开"兜底入口。
  （第二轮截图里 PDF 区显示「无法打开此文件」就是这个原因，不是产品缺陷：
  `/api/jobs/{id}/pdf` 返回 200 + `application/pdf` + 27,383 字节，PyMuPDF 也能正常解析。）
- **桌面窗口只在 Windows 11 + Edge 实测**。macOS / Linux 会走 pywebview 或默认浏览器，
  这两条路径**没有实测证据**。
- **新界面没有在真实付费 API 的完整识别流程下点过一遍**，只用了构造任务 + 真实编译。
  也就是说：界面到后端的字段对接验证过，但"真实上传 → 真实识别 → 核对 → 导出"这条
  完整人工路径还没有人走过。（第二轮补上了"真实上传 → 真实失败 → 面板显示原因"这一段，
  但成功识别那一段仍然依赖真实密钥。）
- **窄屏只在 1024px 以上测过**。≤900px 会切单栏布局，那条分支只做了代码审阅，没有实测截图。
